# Universal rules
- Read the existing code near your change before writing. Match its style.
- Make the smallest change that solves the task. No drive-by refactors.
- Run the tests and the linter before saying done. Report the exact command and result.
- Never invent APIs, flags or package names. If unsure, check the docs or the installed source.
- Never commit secrets, .env files or generated build output.
- Ask before: deleting files, changing public interfaces, adding dependencies, running migrations.
- When a task is ambiguous, state your assumption in one line and proceed.
- Keep commit messages: imperative, under 72 chars, explain why in the body.
